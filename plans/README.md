## Findings considered and rejected (do not re-audit)

- **`idleTimeout: 0` in `apps/server/src/index.ts`**: looks like a DoS gap,
  but raising it kills healthy quiet signaling sockets mid-call without a
  heartbeat design. Needs a keepalive first; out of scope for plan 006.
- **`RTCPeerConnection.restartIce()`**: rejected in favor of fresh-generation
  renegotiation (plan 002) — restart can't recover a closed data channel and
  would add a platform operation for a partial solution.
- **Ephemeral/HMAC TURN credentials**: follow-up to plan 003; static env
  credentials are acceptable for the current single-operator deployment.
- **Opaque-handle `{ value: unknown }` casts in the platform layer**: real
  type-safety debt, but it bought the fake-platform actor tests; a generic
  `PeerSessionPlatform` is a refactor with no behavior change — not urgent.
- **`repos/effect` vendored into git history**: deliberate per AGENTS.md
  (LLM reference); repo-size cost accepted by the maintainer.
- **`RoomService` half-immutability** (copies the Map, mutates `ctx` in
  place): safe under `SynchronizedRef` serialization; style-only. Plans 005/
  006 touch those lines anyway.
- **Duplicate `layer` / `layerTest` on `RoomService`**: cosmetic.
- **Room-code entropy / modulo bias in `apps/web/src/lib/ids.ts`**: ~47 bits
  for room ids; bias from `byte % 26` is negligible at this threat level.
